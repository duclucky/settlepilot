# Goal completion after verified settlement

Approved bug-fix scope, 2026-10-05: retain the exact settled obligation version as the proof binding, while recognizing the single version increment made by payment reconciliation. A real amendment, missing receipt, mode mismatch or changed financial identity must never be accepted as completion.

Acceptance: reconciliation updates goal status and PAY_NOW proof atomically with the verified payment; existing settled goals can be refreshed without another LLM/provider call or transaction. Durable restart and repeat reconciliation do not change versions or resubmit money. Installer and hosted backend receive the same fix. Operational history and credentials are retained; Agent remains paused after deployment.

Root cause: the receipt stores the pre-payment obligationVersion. Engine reconciliation marks the obligation paid and increments its version, but goal refresh previously rejected that version before checking receipt identity. Reconciliation also did not refresh goal status immediately. The fix matches the receipt to the plan's original version, accepts the one-step settlement transition only with matching financial identity and a verified/simulation-labelled outcome, and refreshes goals in the same SQLite transaction. Same-version verified historical fixtures remain compatible. Other version changes stay superseded; unknown/provider/hash-only outcomes do not complete goals.

Four new offline regressions cover the real engine reconciliation path, restart and repeated reconciliation, repair of stored superseded goals without changing money, incorrect identity/amendment/unverified cases and simulation labelling. Before the fix, three tests failed (RECONCILING/SUPERSEDED instead of COMPLETED); after the fix, all 300 installer tests and 351 hosted tests pass, along with installer build and both hosted builds. No live provider or transaction is needed to apply this correction to already-verified stored receipts.
